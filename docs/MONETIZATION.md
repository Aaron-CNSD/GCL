# GCL 保持用户免费时的收入方案

用户不用付费可以做到；收入仍然来自赞助商、广告商、平台或内容受众。使用量本身不会自动变成收入，也不能承诺固定收益。

## 推荐顺序

| 模式 | 谁付钱 | 用户是否需要买启动器 | 开始前需要做什么 | 当前状态 |
| --- | --- | --- | --- | --- |
| 企业 / 开源项目赞助 | 愿意支持维护的企业或机构 | 不需要 | 证明项目能稳定使用，准备真实的版本、使用反馈和维护记录，再谈合同与展示范围 | 尚无已签约赞助 |
| 原创教程内容的平台收益 | 视频平台的广告或创作计划 | 不需要 | 制作有实质内容的安装、模组和联机教程，满足平台要求并申请结算 | 未开通或承诺收入 |
| 自己的原创模组 / 整合包平台收益 | 相关平台的创作者收益池 | 不需要购买启动器 | 发布自己有权发布的作品，按平台规则取得真实流量与结算资格 | GCL 调用下载 API 不等于参加收益计划 |
| 官网公开标识的合作位 | 合作方 | 不需要 | 明确标注赞助 / 广告，先核对 Minecraft 和平台规则，再协商真实合作 | 当前软件和网站没有植入商业广告 |

## 适合现在的做法

先把完整游戏启动、整合包兼容性和双机联机做实测，解决影响使用的问题。持续更新使用指南与演示，积累真实反馈；在有稳定的使用价值后，把企业赞助作为优先方向。赞助不应把下载或核心功能锁起来。

可以准备一份简短合作说明：项目定位、当前版本、已验证与未验证功能、维护计划、合作展示位置以及反馈方式。不要编造用户数量、下载量、收入或现成合作方。

GitHub Sponsors 只对符合支持地区及其他资格的贡献者开放；收款、实名及税务等步骤须由你本人按平台要求完成。本次没有开设收款账户、接入广告 SDK、申请或签署商业合作。

## 两个容易误解的点

1. Modrinth 的收益机制面向平台作品创作者，并依据其规则计算；把 Modrinth API 接入另一个启动器，不会让启动器维护者自动按下载获得报酬。
2. Minecraft 的视频与商业使用规则有具体条件。原创视频广告、赞助展示等需按规则操作，不能把“保持用户免费”理解为任何广告合作都自动获准。
